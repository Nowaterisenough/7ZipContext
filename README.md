# 7-Zip Context

Windows 11 右键菜单、压缩工作台和常驻托盘程序。压缩引擎直接编译自 7-Zip 源码，不需要另行安装 7-Zip。

## 界面与使用

运行 `7ZipContextApp.exe` 打开工作台，或使用 `7ZipContextApp.exe --tray` 仅驻留托盘。

- **左键单击托盘**：打开或收起弹窗。默认保持置顶显示，移开鼠标或切到资源管理器选择文件时不会消失，方便拖入文件和文件夹；再次单击托盘图标、点击右上角关闭按钮或在弹窗内按 Esc 收起，后台任务继续运行。弹窗包含解压、压缩、任务、设置四页；右上角可以展开为主窗口。
- **右键单击托盘**：打开主窗口或退出。关闭主窗口会保留托盘，正在进行的任务继续执行。
- **全部拖入，再开始**：在主窗口或托盘的解压页拖入混合文件、多个文件夹或整个目录，软件后台扫描、识别并加入队列。可以继续添加其他文件，调整保存位置和选项；只有点击“开始解压”后才进行解密、解压及整理。“添加文件”“添加文件夹”使用相同流程。保存位置留空时使用系统下载文件夹下的“整理结果”。扫描可取消，主窗口和托盘共享队列、进度及结果。
- **托盘快捷解压**：托盘小窗口的“开始解压”位于解压页最上方，打开即可操作，无需滚动到设置下方；没有输入或任务运行时自动禁用。
- **已有媒体**：原本就是视频或图片的文件会按来源文件夹归组，复制到保存位置，经过 SHA-256 核验后整理到“视频/图片”。源文件保留。确认没有压缩格式特征的普通 PDF、TXT、安装包等辅助输入会统计为忽略项；无法确认的大文件、缺卷或读取错误会明确列出，不把它们静默当作成功。
- **密码列表**：在“设置 → 密码”中直接添加或导入密码，无需填写名称。每行显示一个密码，双击或按“编辑”修改，支持多选后点击“删除”或按 Delete；勾选表示启用。重复密码合并显示，编辑和删除会作用于旧密码库中该密码的所有副本，停用某个密码不会影响其他密码。支持按密码搜索，主窗口与托盘即时同步；大小写和首尾空格保持原样。
- **首页快捷添加密码**：主窗口和托盘的解压首页提供密码输入框，输入后按回车或点击“添加密码”即可保存，也可点击“密码列表”管理。本次解压临时使用的密码仍可填写在“本次密码”中，不会自动保存。
- **自动解密**：开启“自动尝试密码”后，解压、检测完整性和修正名称会自动尝试列表中勾选的密码。本次密码优先，同一批次和本次会话中已命中的密码会优先复用。支持加密文件名的压缩包及完整分卷；没有匹配密码时显示失败，不创建解压输出目录。匹配过程可暂停和取消，任务只显示“密码列表”或“随包密码说明”等来源类别，不显示来源名称或密码内容。
- **随包密码说明**：自动使用密码单时，也会从输入及本次解压生成的 TXT 中读取密码候选。仅处理名称包含“密码”或 `password`、或名为 `pwd` 的小型文本，支持“解压密码：值”等标签。只把文本作为候选密码，不执行其中的指令；候选仅用于本次任务，不自动保存到密码库，报告不输出密码内容。
- **自动解压内层**：默认开启。点击“开始解压”后，程序会识别每层新生成的文件，继续解压内层压缩包，直到没有内层压缩包，并汇总视频数量。按文件头识别伪装扩展名；本层输出中分散在不同子目录的同组分卷可直接关联读取，无需移动或复制。整条嵌套分支成功后，自动删除该分支的中间压缩包及分卷，保留最初添加的压缩包。重名分卷不会混组；缺卷、密码不匹配和损坏会显示失败。关闭开关则只解压外层。
- **继续尝试 PDF**：解压产生的 PDF 也会作为候选压缩包处理，检查文件头、ZIP 尾部目录和分卷信息，并尝试压缩引擎。支持伪装成 PDF 的压缩包、ZIP/ZIP64 尾卷及引擎搜索范围内的内嵌压缩数据。普通 PDF 尝试后作为辅助文件，在媒体整理成功时清理；没有媒体时保留。无法识别的二进制 PDF、缺卷或缺密码会报告失败并保留。
- **仅保留视频和图片**：默认开启。每个最外层压缩包对应一个独立子文件夹，完整解压后将所有层的视频、图片分别整理到其中的“视频”和“图片”目录，再删除本次生成的其他解压文件及空目录。同名文件自动加编号，图片或视频缺少扩展名时按识别结果补齐。开启此选项时自动使用独立目录和完整的内层解压；关闭后恢复原有布局。
- **长路径解压**：文件、内层压缩包和输出目录的完整路径超过 260 个字符时，使用 Windows 扩展路径完成读取、扫描、解压、核验、分类及中间文件清理，保留原文件名。仍执行路径穿越、链接和已有文件保护；输出创建失败时报告 Windows 错误码。
- **智能识别**：读取文件头识别 7z、ZIP、RAR/RAR5、TAR、GZip、BZip2、XZ、ISO、CAB。支持错误扩展名；选中项目后点击“修正名称”，确认引擎可打开后再改名。目标名称存在时不会覆盖。
- **视频伪装 ZIP**：对文件头未识别的文件检查末尾 256 KB 内的 ZIP/ZIP64 目录，核对目录、ZIP64 定位器及本地文件头后定位压缩数据。支持很大的视频前缀、ZIP64 扩展字段和少量尾部填充；即使传统结束记录没有溢出标记，也会处理其前面的 ZIP64 结束记录。直接在原文件上读取压缩数据范围，无需先裁剪复制。普通 MP4 或仅含相似字节的文件不会据此当作压缩包。
- **视频伪装 7z**：在文件前 64 KB 内查找完整的 7z 起始头并核对 CRC，支持 MP4 的 `ftyp/free` 结构中藏有 7z 的文件。直接从原文件中的压缩包偏移读取，拖入扫描和自动解压内层均适用；加密包继续使用密码单。只有相似标记的普通视频不会误判，起始头有效但后续数据损坏或缺失时报告解压失败。
- **分卷识别**：自动归组 `.001/.002`、`.part1.rar/.part2.rar`、`.rar/.r00`、`.zip/.z01`。添加任意一卷会定位入口并去重；缺首卷、编号断档会提示，完整性检测进一步检查损坏或缺少末卷。
- 数字分卷可以在卷号后多一层伪装扩展名，例如 `课程.7z.001.pdf` 和 `课程.7z.002`。也支持省略压缩格式名的 `p.001.pdf/p.002.pdf`，以及卷号中插入“删除中文”“删掉”“删”等提示的 `YWNS888.7z.00删除中文1/00删除中文2`。拖入任意一卷或整个目录，点击“开始解压”即可；内层和跨目录分卷使用相同规则。没有压缩格式名的候选组须有真实压缩包文件头，普通编号 PDF、图片和 Office 文档仍按普通文件处理；不同目录的同名独立组分别判断。
- 数字分卷按内容区分字节切分与原生 RAR/RAR5：前者拼接读取，后者映射为引擎所需卷名逐卷读取；带有效伪装前缀的 7z 分卷从真实文件头偏移读取。全过程不修改源文件名或内容。缺首卷、编号断档、重复编号及未使用的候选卷会报告错误，失败分支保留中间文件。
- **多文件夹中的同名分卷**：数字分卷及 `partN` 分卷按目录层级区分独立组。例如 `A/分卷1/name.7z.001` 与 `A/分卷2/name.7z.002` 可以自动合并，同时添加 `B/name.7z.001/.002` 时，B 中的副本独立处理，不会拆散 A 中的分卷。整目录、多个文件夹混合添加和内层递归均适用；分批添加时结合当前队列重新归组，刷新也保留跨目录的全部卷。相同编号存在多个无法按目录区分的候选时仍报告失败，不借用另一组的卷来拼凑。
- **尾卷跨层关联**：原生 ZIP/ZIP64 尾卷可按目录信息关联同批输入里的前置卷，支持 `name.z01`、`name1`、`name.001`、`name.zip.001` 等名称。先解开外层包，再将新出现的尾卷与原始数据卷关联；同层已归组的卷不重复处理。读取时映射卷名，不改名、不移动原始输入；缺少的卷会明确列出，不把不完整的数据当作整理成功。
- **伪装分卷后缀**：同组 `partN` 分卷的扩展名可以各不相同，例如 `资料.part1.rar` 和 `资料.part2.r删ar`。软件按共同名称、卷号和文件头识别 RAR/RAR5 分卷或需要拼接的 7z/ZIP 分卷，不改动原文件。从任意一卷、两卷一起或整个目录拖入均可；点击“开始解压”后读取整组，内层分卷也使用相同规则。若同一编号有多个候选，或压缩引擎没有用到全部候选卷，程序报告错误并保留文件。
- **检测完整性**：真实解码和 CRC 校验，报告密码错误或损坏，不写出解压文件。“修正名称”不代表修复损坏的数据；程序不能重建丢失的数据或分卷。
- **压缩**：支持文件、文件夹、多项输入，7z/ZIP、快速/标准/极限压缩、密码加密以及自定义分卷。ZIP 密码使用 AES-256。
- **分卷大小**：留空为不分卷；预设 100 MB、1 GB，也可输入 `512K`、`250M`、`2G`，纯数字按 MB 处理。生成标准字节分卷 `name.7z.001` 或 `name.zip.001`，全部放在同一目录后打开首卷。
- **任务**：显示本次会话中的真实任务结果、完成字节、速度图、进度，可暂停、继续、取消并打开输出目录。

界面以 [JX3DPS 的 develop 分支](https://github.com/Nowaterisenough/JX3DPS/tree/2686421e38144c4a3740e43722f2fcbce7825857/apps/desktop/controls/theme)中的 Qt Widgets Magpie 实现为基础：`DarkStyle`、`NavigationStrip`、`SegmentedTabBar` 及相同的切换动画。文字以原始 PNG 和 Windows 原生渲染结果校准，Qt 优先使用 Segoe UI，中文回退到微软雅黑，匹配参考的 110% 文字缩放和各类文字的尺寸、粗细。页面使用常驻 `QStackedWidget`，主窗口和托盘共享设置和任务状态。来源与适配范围记录在 `src/ui/REFERENCE.md`。

外壳按原始 Magpie 截图校正：居中纯文字页签、右上角刷新/设置、独立的设置子页签及搜索，不显示额外的面包屑或引擎状态行。主窗口使用居中的最大内容宽度及随窗口变化的留白，滚动条位于窗口最右侧；托盘默认宽度为 480 逻辑像素（125% 缩放下为 600 像素）。主要操作和图表强调色为 `#A5B4FC`。

压缩密码、“本次密码”及命中缓存只保存在当前进程内存中。通过“添加密码”或导入文件保存的密码使用 Windows DPAPI 按当前账户加密，保存到 `%LOCALAPPDATA%\7ZipContext\password-lists.dat`，重启后仍然可用；原始文本文件不修改。密码文件支持 UTF-8、带 BOM 的 UTF-16、GBK/GB18030，自动去重并跳过空行，保留大小写及行首、行尾空格。单个导入文件最多 8 MB，密码库合计最多保存 100000 个密码，加密存储最多 32 MB。

自动使用密码单、托盘弹窗自动收起、记住窗口尺寸和主窗口位置写入 `%LOCALAPPDATA%\7ZipContext\desktop.ini`。托盘自动收起默认关闭，旧版默认自动收起设置不再沿用；如需点击外部收起，可在设置中手动开启。压缩密码与解压密码分开管理；没有默认添加开机启动。

旧版本的密码库无需重新导入，原启用状态和注释数据继续保留。界面直接管理密码值，不再要求选择来源密码单；注释不参与密码尝试。

## 在线更新

进入“设置 → 关于 → 在线更新”检查版本、下载更新，然后点击“安装并重启”。默认在启动后检查正式版，也可关闭自动检查。解压、压缩或扫描任务运行时不能安装更新。命令行自动解压及启动检查不会触发在线更新。

更新来源为项目 GitHub Releases。下载前核对仓库与版本对应的附件名称，下载后校验长度和 `SHA256SUMS.txt` 中的 SHA-256；下载可取消，校验失败不能安装。当前公开版本尚未提供对应更新附件时，会明确提示缺少可校验更新包。

如果下载中断、字节数不符或哈希不匹配，程序会丢弃本次下载，通过 GitHub 的附件 API 重新下载同一个包，再按原清单校验。两次都失败时会显示具体原因；点击“重新下载”即可重试，不必重新检查版本。

“安装并重启”和托盘菜单中的“退出”会结束应用进程，不受普通窗口“关闭后收回托盘”的行为影响。如果更新组件失败或异常退出，仍在运行的界面会显示错误并恢复重试入口，已校验的安装包保留；重试会归档上一份更新结果。

便携版通过完整 ZIP 更新运行库，逐文件验证 `update-manifest.json`，备份原程序文件并在替换后执行启动检查；失败时回滚。未列入发行清单的文件保留，旧清单中已被用户修改的废弃文件也保留。备份位于程序目录的 `.7zipcontext-update-backup-*`，下载与更新结果位于 `%LOCALAPPDATA%\7ZipContext\updates`。程序目录必须可写。

通过项目 MSI 安装的版本使用 MSI 升级，安装时 Windows 会请求管理员权限；取消授权或安装失败会报告结果。密码单与设置位于 AppData，不随程序文件替换。手动填写但尚未保存的密码、队列及任务记录不会跨重启保留。

## 输出行为

默认按压缩包名称建立独立输出目录，目录已存在时添加数字后缀；“直接解压”保存到指定位置。现有文件不会被覆盖。失败或取消的解压可能保留已输出的文件，任务记录会标明。

媒体整理后的目录为 `保存位置/压缩包名/视频/文件` 和 `保存位置/压缩包名/图片/文件`。整个最外层压缩包的所有嵌套任务成功后才整理；全部媒体移动并核验成功后才清理 TXT、HTML、安装包等其他解压产物。没有视频或图片时保留解压内容并提示。失败、取消、文件被修改或占用时保留尚未清理的文件；部分已移动的媒体会在任务报告中记录实际位置。仅处理本次生成的文件，原始压缩包和输出位置已有的文件均保留。

加密压缩包先使用候选密码进行无输出的完整校验，确认可用后再解压；因此匹配到正确密码后仍需读取数据完成解压。未加密的压缩包直接处理，不逐个尝试密码单。

引擎明确报告缺卷、数据截断或不支持的压缩/加密算法时，停止尝试密码并显示对应原因。密码错误与加密数据损坏无法区分时仍保留两种可能；密码单没有正确密码的文件需要补充密码后重试。

自动解压内层只检查本次成功写出的文件，不扫描输出位置中原有的文件。内层使用独立子目录；找到视频后仍会处理其他待解压分支。所有解压任务处理完毕后，从最深层开始清理成功分支的中间包。内层失败或达到限制时，其祖先中间包保留以便重试；取消会停止后续清理。清理前核对本次生成记录、输出目录范围及文件身份，文件被更改或占用时保留并提示。此阶段仅删除中间包，其他文件由后续媒体整理选项决定是否清理；原始压缩包和已有文件始终保留。程序只移除已记录且为空的解压目录，不使用递归目录删除。

APK、Office 文档、EPUB 等使用 ZIP 容器的成品格式不自动拆开或作为中间包清理。开启“仅保留视频和图片”时，它们会在媒体整理成功后作为其他解压文件清理；关闭时原样保留。其他扩展名伪装仍按真实文件头识别；例如扩展名为 `.apk`、实际内容为 7z 的文件仍会继续解压。用户直接添加的 ZIP 容器文件仍可手动解压。

任务显示当前层级和动态增加的压缩包组数，结束时汇总视频数量及清理数量、大小。最多自动处理 32 层、1000 组，达到限制会明确报告未完成。

同一程序也提供无窗口的自动解压入口，使用已保存的密码单并输出进度和结果 JSON。输出目录、报告路径需为绝对路径，报告文件不能已存在：

```powershell
./7ZipContextApp.exe --extract-auto --output "D:\自动解压" --report "D:\解压报告.json" "D:\example.7z.001"
```

路径参数也可以直接传入整个目录，或同时传入文件、目录、分卷及普通媒体；命令行显式执行 `--extract-auto` 相当于加入输入并点击开始，与界面共用扫描和 `ArchiveController::start` 处理流程，从解压、递归到清理、整理均由程序完成：

```powershell
./7ZipContextApp.exe --extract-auto --output "D:\整理结果" --report "D:\整理报告.json" "D:\全部输入"
```

可加上 `--password-list "D:\密码单.txt"`，在开始任务前通过软件导入该密码单并启用。该参数接收绝对文件路径，文件每行一个密码，导入后按 Windows 账户加密保存；命令行参数和报告均不包含密码内容。原始文本文件不会由软件删除。

仅导入密码单而不启动任务时，可使用 `--import-password-list "D:\密码单.txt" --report "D:\导入结果.json"`。

CLI 默认整理媒体并清理其他解压文件；加上 `--keep-layout` 可保留压缩包原有文件布局，仍会自动解压内层并清理成功的中间包。JSON 报告包含输入文件数量、压缩包组数、媒体组数、忽略的辅助文件、关联为内层分卷的 `associatedInputFiles`、整理后的 `videos`/`images` 路径及清理数量和大小。每条任务还记录完整入口 `input`、所属最外层入口 `rootInput`、实际输入文件/分卷 `inputFiles`、层级 `depth` 和类型 `kind`（`archive` 或 `media`），可区分不同目录中的同名内层文件，以及解压与原有媒体复制任务。

可以直接将挂载盘目录作为输入、将本地目录作为输出，例如 `--output "D:\整理结果" --report "D:\整理报告.json" "Y:/"`。程序直接读取来源并写出最终结果，无需外部脚本先解压或整理。报告的 `inputs` 记录原始入口参数；扫描结束后会继续处理，直到整个任务完成才退出。

退出码为 `0` 表示全部解压任务成功，`1` 表示存在失败，`2` 表示参数或报告路径错误。此入口使用与主窗口和托盘相同的解压队列。

压缩在目标目录写入临时文件，成功后再生成最终名称。分卷压缩需要先完成临时整包，再按大小拆分，因此需要额外磁盘空间。失败或取消时移除本次创建的压缩临时文件和分卷。不同输入具有相同顶层名称、输出放在源文件夹内、源目录包含链接时会报告错误。

右键菜单会将所选文件交给工作台，允许先调整设置，点击开始后再执行，不在资源管理器进程内执行耗时的压缩。主程序使用单实例，后续调用把文件转交给现有窗口。

## 构建

要求 Windows 11、CMake 3.20+、Qt 6.6+（Widgets、Network、Svg、Test），以及与 Qt ABI 匹配、支持 C++20 的 MSVC 或 MinGW-w64。优先从已有 `CMakeCache.txt`、`qmake6 -query QT_INSTALL_PREFIX` 或 Qt 安装目录发现工具链。首次构建需要初始化已固定版本的子模块：

```powershell
git submodule update --init --recursive
```

Visual Studio 2022 / Build Tools 与匹配的 MSVC Qt（如果 Qt 尚不在 CMake 搜索路径，添加 `-DCMAKE_PREFIX_PATH=<Qt 安装目录>`）：

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
cmake --install build --config Release
```

MinGW-w64 / MSYS2 UCRT64 与匹配的 Qt（将对应 `bin` 目录添加到当前终端 PATH）：

```powershell
$qtPrefix = qmake6 -query QT_INSTALL_PREFIX
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="$qtPrefix"
cmake --build build
ctest --test-dir build --output-on-failure
cmake --install build
```

`cmake --install` 生成完整的 `build/install` 目录，包括 `7ZipContext.dll`、`7ZipContextApp.exe`、Qt 运行库、平台插件和编译器依赖。从这个目录直接运行 EXE 可以使用完整工作台和托盘，无需注册右键菜单。分发时需保留整个目录，不能只复制 EXE。

## 自动编译与发布

GitHub Actions 工作流为 `.github/workflows/build.yml`，名称是 **Build and Release**。

| 触发方式 | 行为 |
|---|---|
| 推送到 `main` | 编译、测试、打包，通过后自动创建 GitHub Release |
| 推送 `v主版本.次版本.修订号` 标签，例如 `v1.1.0` | 使用标签版本编译并发布 |
| 向 `main` 提交 Pull Request | 编译、测试、打包并保存 Actions artifacts，不发布 Release |
| 在 Actions 页面选择 Run workflow | 可选择是否发布；仅在 `main` 分支且勾选 `publish` 时发布 |

自动版本以当前提交可达的最高 `vX.Y.Z` 标签为基础，将后续提交数量加到修订号；没有标签时使用 `1.0.提交数`。同一提交重跑使用相同版本。版本号同步到程序、MSI、更新清单和包内的 AppxManifest，已有标签指向其他提交时会拒绝发布，不移动标签。标签需要使用三个数字部分；MSI 限制主版本、次版本不超过 255，修订号不超过 65535。

发布附件包括：

- `7ZipContext-版本-windows-x64-msvc.msi` / `-msvc-portable.zip`：MSVC 构建的安装包和便携包。
- `7ZipContext-版本-windows-x64-ucrt.msi` / `-ucrt-portable.zip`：MSYS2 UCRT64 GCC 构建的安装包和便携包。
- 两套 MSI 是同一应用的替代构建；安装同版本的另一套 MSI 会替换现有安装，不并排安装。便携包应解压到各自独立的目录。
- 旧文件名 `7ZipContext-版本-windows-x64.msi` / `-portable.zip` 保留为 MSVC 包的兼容别名，保证旧版本自动更新可用。新版本在线更新只选择自身工具链的附件。
- `SHA256SUMS.txt`：发布附件的 SHA-256 校验值。
- `build-info-msvc.json` / `build-info-ucrt.json`：各自的编译器名称、实际版本、Qt 版本、源码提交和打包检查结果；`build-info.json` 汇总两个构建。

工作流在 `windows-latest` 上并行构建 MSVC 和 MSYS2 UCRT64 两个版本，Qt 固定为 6.12.0。MSVC 动态选择最新已安装的稳定 Visual Studio 和最高版本的 C++ 工具集；UCRT64 先完整更新 MSYS2，再安装仓库中的最新 GCC。两套均用 Ninja，记录实际编译器和 Qt 版本。MSVC Qt 使用兼容的 `win64_msvc2022_64` 二进制包，aqtinstall 固定为支持按架构下载的提交 `5a49f2b391ae8ee1d3c0dd87f8b33c1d49a4deb7`；UCRT64 从 pacman 安装 `qt6-base` 和 `qt6-svg`。配置阶段检查两套 Qt 均与指定版本一致；MSYS2 滚动仓库升级 Qt 后应协调更新 Qt 版本，不能静默混用。

两个构建各自运行八组程序测试、Windows PowerShell 更新/回滚测试、原生界面截图和 MSI/便携包校验，并在隔离 runner 上实际安装 MSI、检查启动和右键菜单、卸载并验证清理结果。MSVC 包携带对应 CRT；UCRT64 包递归收集 GCC、Qt 和插件依赖 DLL，并在只保留系统目录的 PATH 下验证启动。两套均通过后，发布合并步骤核对源码提交、版本、工具链及所有文件的 SHA-256，生成统一校验清单，随后一次性发布全部附件。任一构建或校验失败均不发布。WiX 及扩展固定为 6.0.2，Actions 固定到具体提交。每套的日志、截图和包分别保存在带 `msvc` / `ucrt` 后缀的 Actions artifacts，合并产物为 `windows-x64-release`。

无需配置个人访问令牌，发布使用 GitHub 自动提供的 `GITHUB_TOKEN`；只有发布任务请求 `contents: write` 权限。工作流必须先提交并推送到 GitHub 才会触发。

在 Windows 本地验证打包流程（先安装 .NET 8 SDK，并完成 CMake 构建）：

```powershell
cmake -S . -B build -D7ZIPCONTEXT_VERSION=1.1.0
cmake --build build --config Release
cmake --install build --config Release --prefix build/ci-install
./tests/ReleaseVersionTests.ps1
./scripts/ci/Build-WindowsPackages.ps1 -Version 1.1.0 -Toolchain msvc -InstallDir build/ci-install -OutputDir build/release-local
```

打包时指定 `-Toolchain msvc` 或 `-Toolchain ucrt`，并通过 `-BuildDirectory` 指定生成 `toolchain-info.json` 的构建目录（默认为 `build`）。脚本核对实际构建元数据与所选工具链；MSVC 自动复制 x64 CRT，UCRT64 由 CMake 部署对应运行库。输出目录必须为空。脚本只构建并核验安装包，不会安装 MSI 或注册本机右键菜单。

## 测试

`ArchiveTests` 在当前工作目录创建独立测试目录，不触碰用户文件。集成测试覆盖 7z/ZIP 加密往返、分卷重组、错误密码、错误扩展名修正、缺卷、CRC 错误回传、取消操作、目录穿越和文件覆盖保护，也覆盖超过 260 字符路径中的原生 ZIP 分卷发现、校验、解压及同名文件保护。

`ArchiveUiTests` 通过 Qt 离屏平台验证连续切页时控件不重建、输入不丢失、主窗口与托盘同步、分段控件的选中位置、密码单管理与编辑，以及从界面触发的真实压缩、修正名称、检测、解压和拖放。离屏截图用于功能诊断，不能代替 Windows 字体效果验收。测试日志位于 `build/ui-tests.log`。

`PasswordTests` 使用临时目录验证文本编码和空格保留、DPAPI 加密保存、损坏库不被覆盖、密码尝试顺序、ZIP AES/7z 加密文件头及分卷、无匹配不输出、批量命中缓存、禁用及暂停取消。存在本机 RAR 分卷测试样本时，还验证加密文件头与跨卷密码匹配。日志位于 `build/password-tests.log`。

`NestedArchiveTests` 验证三层嵌套、不同层的不同密码、扩展名伪装、跨目录加密分卷、同名分卷隔离、内层缺卷错误、关闭递归、取消，以及直接解压不会处理输出目录中原有的文件。还覆盖 PDF 探测、ZIP/ZIP64 尾卷与外部原始数据卷关联、同层分卷只处理一次，以及随包密码说明的启用/禁用和不持久化。长路径测试验证内层包和图片超过 260 字符时仍能解开、保留名称、移动分类、清理及重新扫描。同时验证成功后删除中间包、失败分支保留祖先、原始分卷保护，以及被修改、占用、取消清理的文件整组保留。日志位于 `build/nested-tests.log`。

`MediaOrganizationTests` 验证跨层媒体分类、同名文件编号、缺扩展名图片识别、媒体移动后内容一致、只删除本次其他解压文件、空目录清理，以及无媒体、内层失败、占用、更改、取消时保留内容。日志位于 `build/media-tests.log`。

`InputDiscoveryTests` 验证混合目录展开、分卷自动补全、重复输入去重、辅助文件识别、普通媒体复制校验、空目录跳过、无法识别输入的错误回传及取消后台扫描。实际 Qt 拖放事件覆盖主窗口/托盘、多个文件/整个文件夹，验证连续添加只更新队列且不产生输出，点击“开始解压”后统一完成整理。命令行自动入口也验证取消扫描不会启动解压。日志位于 `build/input-tests.log`。

`UpdateTests` 使用模拟网络验证正式版版本号、仓库附件路径、重复附件/校验条目、下载末尾数据、SHA-256 不匹配、HTTP 失败、跳转限制及取消重试。`UpdateHelperTests.ps1` 在隔离目录中使用真实运行库验证完整替换、原文件备份、路径穿越拒绝、清单校验、无关文件保留及启动失败回滚。失败启动由合法的测试 EXE 返回错误码模拟，不通过损坏系统或 Qt DLL 触发 Windows 错误弹窗。测试不会安装 MSI、停止常驻程序或修改实际安装目录。

`DesktopLifecycleTests` 在独立进程中验证主窗口、托盘弹窗、两个窗口同时显示和全部隐藏时均可明确退出；离屏测试模拟托盘存在时的关闭行为，防止“关闭后收回托盘”拦截更新退出。更新测试还覆盖组件失败、无结果退出、损坏结果及重试恢复。

在 Windows 上生成使用原生字体后端的界面预览，不显示或激活桌面窗口：

```powershell
cmake --build build --target RenderUiReferences
./build/RenderUiReferences.exe ./build/native-previews
```

MSVC 多配置构建需添加对应的 `--config Release`，程序位于 `build/Release`。预览目录中的 `render-info.json` 记录实际 DPI、字体和像素尺寸；视觉检查以这些原生渲染图为准。

另可将本机生成的加密 RAR 分卷作为参数传给 `ArchiveTests.exe`：密码为 `test-secret`，内容为同目录下的 `payload.bin`。测试会验证加密文件头、跨卷解压、字节一致性和缺少末卷的错误回传。

桌面验收路径：运行 EXE → 关闭主窗口 → 单击托盘 → 添加/拖入全部文件或文件夹 → 选择保存位置 → 点击“开始解压” → 自动进入任务页并产出整理结果 → 切换压缩页生成分卷 → 展开主窗口。还应检查多显示器 DPI 切换、重复单击托盘、文件选择窗口打开时弹窗保持可用，以及暂停后关闭窗口仍可继续任务。

## 安装程序和右键菜单

MSI 默认安装到 `C:\Program Files\7ZipContext`，在开始菜单创建“7-Zip Context”入口，并在 Windows 安装记录中保存安装位置。普通安装无需开发者模式；文件和文件夹的常规右键菜单提供“解压并整理”和“添加到压缩包”，Windows 11 上可从“显示更多选项”进入。

程序文件内嵌多尺寸 Windows 图标，开始菜单快捷方式和已安装应用使用同一个“7”标志。稀疏包包含对应尺寸的开始菜单图标。图标源于程序已有的绘制代码，可构建 `ExportAppIcon` 目标并运行 `ExportAppIcon.exe <输出目录>` 重新生成 ICO 和 PNG；生成过程不显示桌面窗口。

Windows 11 新式一级右键菜单依赖稀疏包身份。目前未签名的稀疏包只会在系统已允许开发模式时尝试注册；策略不允许或注册失败时保留完整桌面程序和常规右键菜单，不回滚 MSI。安装器不会开启开发者模式、导出私钥、添加受信任证书或强制重启资源管理器。可选注册日志位于 `%LOCALAPPDATA%\7ZipContext\registration.log`。

便携版完整解压后直接运行 `7ZipContextApp.exe`。如已自行配置允许开发模式，可以用以下脚本尝试注册当前用户的新式右键菜单：


```powershell
cd build/install
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

如果资源管理器尚未刷新新菜单，可以自行重新启动资源管理器或注销登录。仓库同时维护 WiX MSI 和 Inno Setup 打包配置，两者均包含桌面程序。

仅移除由当前程序目录注册的新式右键菜单：

```powershell
powershell -ExecutionPolicy Bypass -File .\uninstall.ps1
```

MSI 程序及其常规右键菜单通过 Windows“已安装的应用”卸载。上述脚本不删除密码单或其他程序文件。
